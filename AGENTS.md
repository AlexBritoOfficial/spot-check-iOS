# spot-check-iOS

Native SwiftUI app (Swift 6.0, Xcode 16.2 toolchain). Project structure
is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from
`project.yml` — **never hand-edit `SpotCheck.xcodeproj`**; edit
`project.yml` and run `xcodegen generate`.

## Build configs

Four configs (`Debug`/`QA`/`Staging`/`Release`), each with its own
`Config/*.xcconfig` and scheme. See `README.md`'s "Environments" table
for which points at what. `Config/Secrets.*.xcconfig` files are
gitignored real values — `Config/Secrets.*.example.xcconfig` are the
committed templates.

## Schema

`supabase/` here is being phased out in favor of `spot-check-backend`,
which is now the schema's source of truth (see README). Don't add new
migrations here — add them in `spot-check-backend` instead.

## Testability

The `SpotCheck` target sets `ENABLE_TESTABILITY: YES` in every config
(not just Debug) — Release-type configs (QA/Staging/Release) disable it
by default, which would otherwise break `SpotCheckTests`' `@testable
import SpotCheck` under those schemes.

`AppEnvironmentTests` runs hosted inside the real `SpotCheck` app
process (standard Xcode unit-test behavior for a target with a host
application dependency) — which means it only actually executes if the
app can launch without crashing. `SupabaseClientProvider` eagerly
initializes a Supabase client from `AppEnvironment` near app startup,
and `AppEnvironment` deliberately `fatalError`s rather than silently
falling back when a config's Supabase secrets are missing or malformed.
So until a config's real `Secrets.*.xcconfig` exists, its scheme builds
fine but its test action can't run at all — not a bug in the test,
expected until Alex provisions that hosted project.
